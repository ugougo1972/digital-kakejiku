# 1. 目的

本書は PowerModules.pretty に登録するフットプリントの
設計判断（Design Rationale）を記録する方法を定義する。

本書の目的は

「何を作ったか」

ではなく

「なぜその設計を採用したのか」

を将来に残すことである。

---

# 2. 適用範囲

本書は以下に適用する。

・新規フットプリント

・仕様変更

・寸法変更

・Pad変更

・レイヤー変更

・レビュー結果

---

# 3. Design Rationaleとは

Design Rationaleとは

設計判断の背景

採択理由

不採択理由

将来見直す条件

を記録することである。

# 8. 記録例

## USB_C_Breakout_6Pin

### 項目

原点

---

採択案

```
基板中心
```

---

不採択案

```
Pad1中心
```

---

採択理由

左右対称部品では

・機械設計

・PCB配置

・レビュー

が容易になるため。

---

不採択理由

Pad1基準では

左右対称性が失われ

固定穴管理も複雑になる。

---

将来見直し条件

左右非対称部品で

基板中心が適切でない場合。

---

影響範囲

全フットプリント

---

## USBシェル寸法

採択案

```
7.40mm
```

実測

```
7.42
7.39
```

採択理由

個体差を吸収するため。

---

## Pad

採択案

```
Pad番号のみ
```

---

不採択案

```
Padへ信号名付与
```

---

採択理由

信号管理を

回路図へ集約するため。

---

## F.SilkS

採択案

端子名称表示

```
VBUS
GND
CC1
D-
D+
CC2
```

採択理由

配線確認性向上。

---

## 保存手順

採択案

```
保存

↓

エディタ終了

↓

ライブラリ再読込
```

採択理由

保存失敗を確実に検出できる。
